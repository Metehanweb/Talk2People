1. Controller / Route (Trafik Polisi)
Görevi: İstemciden (tarayıcı, mobil uygulama vb.) gelen HTTP isteklerini (GET, POST, PUT,
DELETE) ilk karşılayan yerdir. Gelen isteğin formatını kontrol eder, ilgili Manager/Service'e
yönlendirir ve oradan dönen sonucu uygun bir HTTP statü koduyla (200 OK, 201 Created, 400
Bad Request vb.) istemciye geri yollar. Asla ve asla iş mantığı (business logic) veya
veritabanı sorgusu içermemelidir.
FastAPI: APIRouter kullanılarak tanımlanır. Parametreleri Pydantic şemaları ile doğrular
ve dependency injection (Depends) ile manager'ı çağırır.
Next.js API: app/api/users/route.js dosyalarındaki export async function
GET(req) gibi fonksiyonlardır. İstek gövdesini alır, manager metoduna gönderir ve
NextResponse.json() ile yanıt döner.
Nest.js: @Controller('users') dekoratörüyle işaretlenmiş JavaScript sınıflarıdır.
İçerisinde @Get(), @Post() gibi yönlendiriciler bulunur ve constructor üzerinden enjekte
edilen Service'i (Manager) çağırır.
Spring Boot: @RestController ve @RequestMapping("/api/users") ile işaretlenmiş
Java sınıflarıdır. Endpointler @GetMapping, @PostMapping ile belirlenir.
2. Manager / Service (Beyin / İş Mantığı Katmanı)
Görevi: Projenin kalbidir. Kontrolcüden gelen veriyi alır, "iş kurallarını" (business rules) uygular.
Örneğin; "Kullanıcı kayıt olurken e-posta daha önce alınmış mı?", "Sipariş verilirken stok yeterli
mi?", "Parola doğru şekilde hashlenmiş mi?" gibi tüm soruların cevabı buradadır. Gerekirse
birden fazla Repo'yu çağırıp orkestrasyon yapar.
FastAPI: Temel bir Python sınıfıdır (class UserManager:). Gerekli repoları (örneğin
UserRepo) __init__ veya metod parametreleri ile alır.
Next.js API: Standart bir JavaScript (ES6) sınıfı olarak kurgulanır. İçerisinde statik veya
instance metodları barındırır ve UserRepo'yu içe aktararak kullanır.
Nest.js: @Injectable() dekoratörü ile işaretlenmiş sınıflardır (UserService). Nest'in IoC
(Inversion of Control) konteyneri tarafından yönetilir ve Controller'lara otomatik enjekte
edilir.
Spring Boot: @Service anotasyonu ile işaretlenen Java sınıflarıdır (UserManager
implementasyonu). @Transactional gibi anotasyonlarla veritabanı işlemleri toplu halde
(rollback destekli) burada yönetilebilir.
3. Repo / Repository (Veritabanı Bekçisi)
Görevi: Veritabanı ile doğrudan konuşan tek katmandır. ORM (Mongoose, Prisma, Hibernate
vs.) sorguları sadece burada yazılır. Manager, veritabanının MongoDB mi yoksa PostgreSQL
mi olduğunu bilmez; sadece Repo'daki findByEmail veya create gibi fonksiyonları çağırır.

FastAPI: SQLAlchemy'nin Session nesnesini kullanarak veritabanına sorgu atan Python

Next.js API: Mongoose modellerini (UserModel.findOne(...)) veya Prisma Client'ı

İşte bu kurallar ve senin seçtiğin 4 teknolojide nasıl uygulanacaklarına dair örnekler:
1. Tek Yönlü Bağımlılık Kuralı (The Dependency Rule)
Kural: Trafik her zaman dışarıdan içeriye (yukarıdan aşağıya) doğru akar. Controller ->
Manager -> Repo -> Model yönü asla tersine çevrilemez. Bir Repo, Manager'ı çağıramaz; bir
Manager, HTTP Request/Response nesnelerini (Controller'ın işi) bilemez.
FastAPI: user_router.py dosyasında user_manager.py import edilir. Ancak
user_manager.py içinde asla FastAPI'nin Request veya Response objeleri bulunmaz,
sadece veri (Pydantic şemaları) ve repo bulunur.
Next.js API: app/api/users/route.js dosyası HTTP statü kodlarını (200, 404) bilir.
Ancak UserManager.js sadece JavaScript objeleri fırlatır (throw new Error("Kullanıcı
bulunamadı")), route.js bu hatayı yakalayıp 404'e çevirir.
Nest.js: Sınıf yapılarında bu kural Dependency Injection (DI) ile korunur.
UserController.js'in constructor'ına UserService enjekte edilir. UserService'e ise
UserRepository enjekte edilir. Asla tam tersi olmaz.
Spring Boot: @RestController sınıfı @Service sınıfını çağırır. @Service ise
@Repository arayüzünü (interface) çağırır. Döngüsel bağımlılık (Circular Dependency)
yaratmaktan kesinlikle kaçınılır.

2. Şişman Manager, Zayıf Controller ve Repo (Fat Service, Skinny
Controller/Repo)
Kural: Akıllı olan tek katman Manager'dır. Controller sadece "gelen veriyi al ve ilgili manager'a
ilet" diyen bir sekreterdir. Repo ise sadece "veritabanına git ve şu sorguyu çalıştır" diyen bir
işçidir. İş mantığı, if/else blokları, hesaplamalar, yetki kontrolleri sadece Manager'da olur.
FastAPI: router.post("/users") endpoint'i sadece 3-4 satırdır. Gelen veriyi alır ve
return manager.create_user(data) der. E-posta formatı doğru mu, şifre yeterince
güçlü mü gibi kontroller UserManager içindedir.
Next.js API: Route içindeki POST(req) fonksiyonu Mongoose veya Prisma modelini direkt
çağırmaz. Sepete ürün eklerken stok kontrolü yapılması gerekiyorsa, bu mantık
product.manager.js içindeki checkStockAndAdd() gibi bir fonksiyonda yazılır.
Nest.js: @Get() metodunun içi bomboştur, sadece return
this.userService.findAll() yazar. Tüm karmaşık algoritmalar Service sınıfının içine
gizlenir.
Spring Boot: @Transactional anotasyonu @RestController'da değil, @Service
katmanındaki metodlarda kullanılır. Böylece bir hata çıkarsa tüm veritabanı işlemleri
(rollback) Manager seviyesinde geri alınır.
3. Modelleri Asla Dışarı Sızdırma (DTO Kuralı)
Kural: Veritabanı modelin (Entity/Schema) ile dış dünyanın (Client/Frontend) doğrudan temas
kurmasına asla izin verme. Araya her zaman DTO (Data Transfer Object) veya Schema koy.
Bu, şifre gibi hassas verilerin yanlışlıkla API'den dönmesini ve "Mass Assignment" (kullanıcının
JSON'a fazladan is_admin: true ekleyerek kendini admin yapması) zafiyetlerini engeller.
FastAPI: Veritabanı sorgusundan dönen SQLAlchemy modelini direkt döndürmezsin.
Route'ta response_model=UserResponseSchema kullanarak, Pydantic'in şifre alanını
otomatik olarak filtrelemesini sağlarsın.
Next.js API: Mongoose'dan dönen kaydı (userDoc) direkt NextResponse.json() içine
koymazsın. JS tarafında bir DTO fonksiyonu yazarsın: const toUserDTO = (user) =>
({ id: user.id, ad: user.ad }) ve sadece bunu döndürürsün.
Nest.js: Gelen veriyi (JS class'ı olarak kurgulanmış) DTO nesneleri ve ValidationPipe
ile karşılarsın. İstenmeyen alanlar JSON içinde gelse bile DTO'da tanımlı olmadığı için

from sqlalchemy.orm import Session
from sqlalchemy import select, update, desc
class BaseRepo:
def __init__(self, model):
self.model = model
def get_one(self, db: Session, id: int):
# Varsayılan olarak silinmemiş olanı getir
stmt = select(self.model).where(self.model.id == id, self.model.silindi_mi ==
False)
return db.execute(stmt).scalar_one_or_none()
def get_many(self, db: Session, filters: dict = None, sort_by: str = "id",
desc_sort: bool = False, skip: int = 0, limit: int = 100):
stmt = select(self.model).where(self.model.silindi_mi == False)
if filters:
for key, value in filters.items():
stmt = stmt.where(getattr(self.model, key) == value)
if desc_sort:
stmt = stmt.order_by(desc(getattr(self.model, sort_by)))
else:
stmt = stmt.order_by(getattr(self.model, sort_by))
return db.execute(stmt.offset(skip).limit(limit)).scalars().all()
def create(self, db: Session, obj_in: dict):
db_obj = self.model(**obj_in)
db.add(db_obj)
db.commit()
db.refresh(db_obj)
return db_obj
def patch(self, db: Session, db_obj, obj_in: dict):
# Sadece gönderilen alanları (kısmi) güncelle
for field, value in obj_in.items():
if value is not None:
setattr(db_obj, field, value)
db.add(db_obj)
db.commit()
db.refresh(db_obj)
return db_obj
def soft_delete(self, db: Session, id: int, cascade_relations: list = None):
# Soft cascade: Eğer ilişkili modeller (örn: User -> Posts) verilmişse onları
da soft delete yap
db_obj = self.get_one(db, id)
if db_obj:
db_obj.silindi_mi = True
db_obj.aktif_mi = False
if cascade_relations:
for relation in cascade_relations:
16/32
# İlişkili alt kayıtları bul ve soft_delete yap (Manager üzerinden
orkestre edilmesi tavsiye edilir)
getattr(db_obj, relation).update({"silindi_mi": True, "aktif_mi":
False})
db.commit()
return db_obj
def hard_delete(self, db: Session, id: int):
# Hard cascade SQLAlchemy modelindeki (cascade="all, delete-orphan") tanımı ile
otomatik çalışır
db_obj = db.query(self.model).get(id)
if db_obj:
db.delete(db_obj)
db.commit()

}
return await this.repo.create(userData);
}

import org.springframework.http.ResponseEntity;

}

400 döner.

user.getEmail());
return ResponseEntity.status(HttpStatus.CREATED).body(response);
} catch (IllegalArgumentException e) {

}
}
